Als Vorlage dient der Controller **Balancing** (Eigenverbrauchsoptimierung, Bundle `+io.openems.edge.controller.ess.balancing+`): klein, vollständig und mit Test. Für Ladepunkte nennt `+CLAUDE.md+` die Bundles `+io.openems.edge.evse.chargepoint.keba+` und `+…mennekes+` als Vorlagen, für Modbus-Geräte siehe xref:development/de/implementing/modbus-device-drivers.adoc[Modbus-Gerätetreiber].

In `+bnd.bnd+` stehen unter `+-buildpath+` neben `+${buildpath}+` alle benötigten OpenEMS-Bundles, hier `+io.openems.common+`, `+io.openems.edge.common+`, `+io.openems.edge.controller.api+`, `+io.openems.edge.ess.api+`, `+io.openems.edge.meter.api+`. `+${buildpath}+` und `+${testpath}+` sind in `+cnf/build.bnd+` definiert (Gson, Guava, OSGi-Annotationen, Logging, JUnit).

[#sec-config-java]
== Config.java

Die Konfiguration ist eine Annotation mit OSGi-Metatype. Daraus entstehen das Formular in der Webkonsole und die Felder, die die UI anzeigt.

[source]
----
@ObjectClassDefinition(name = "Controller Ess Balancing",
        description = "Optimizes the self-consumption by keeping the grid meter on zero.")
@interface Config {
    @AttributeDefinition(name = "Component-ID", description = "Unique ID of this Component")
    String id() default "ctrlBalancing0";

    @AttributeDefinition(name = "Alias", description = "Human-readable name ...")
    String alias() default "";

    @AttributeDefinition(name = "Is enabled?", description = "Is this Component enabled?")
    boolean enabled() default true;

    @AttributeDefinition(name = "Ess-ID", description = "ID of Ess device.")
    String ess_id();

    @AttributeDefinition(name = "Grid-Meter-ID", description = "ID of the Grid-Meter.")
    String meter_id();

    @AttributeDefinition(name = "Target Grid Setpoint", description = "...")
    int targetGridSetpoint() default 0;

    String webconsole_configurationFactory_nameHint() default "Controller Ess Balancing [{id}]";
}
----

* `+id+`, `+alias+`, `+enabled+` hat jede Komponente.
* Ein Unterstrich im Methodennamen wird zum Punkt im Property-Namen: `+ess_id()+` liest die Property `+ess.id+`.
* `+webconsole_configurationFactory_nameHint+` bestimmt den Anzeigenamen in der Webkonsole.

[#sec-interface-mit-eigenen-channels]
== Interface mit eigenen Channels

[source]
----
public interface ControllerEssBalancing extends Controller, OpenemsComponent {
    public enum ChannelId implements io.openems.edge.common.channel.ChannelId {
        DEBUG_SET_GRID_ACTIVE_POWER(Doc.of(OpenemsType.INTEGER)
                .accessMode(AccessMode.READ_ONLY)),
        SET_GRID_ACTIVE_POWER(Doc.of(OpenemsType.INTEGER)
                .accessMode(AccessMode.WRITE_ONLY)
                .onChannelSetNextWriteMirrorToDebugChannel(DEBUG_SET_GRID_ACTIVE_POWER));
        ...
    }
}
----

Hier gibt es einen Write-Channel, über den ein anderer Controller oder eine Schnittstelle den Netz-Sollwert vorgeben kann. `+onChannelSetNextWriteMirrorToDebugChannel+` spiegelt den geschriebenen Wert in einen lesbaren Channel, damit er in Historie und UI sichtbar ist.

[#sec-implementierung]
== Implementierung

[source]
----
@Designate(ocd = Config.class, factory = true)
@Component(
        name = "Controller.Symmetric.Balancing",    // Factory-PID, nie ändern
        immediate = true,
        configurationPolicy = ConfigurationPolicy.REQUIRE)
@GenerateTargetsFromReferences({ "ess", "meter" })
public class ControllerEssBalancingImpl extends AbstractOpenemsComponent
        implements Controller, OpenemsComponent, ModbusSlave, ControllerEssBalancing {

    @Reference(policy = STATIC, policyOption = GREEDY, cardinality = MANDATORY,
            target = "(&(id=${config.ess_id})(enabled=true))")
    private ManagedSymmetricEss ess;

    @Reference(policy = STATIC, policyOption = GREEDY, cardinality = MANDATORY,
            target = "(&(id=${config.meter_id})(enabled=true))")
    private ElectricityMeter meter;

    private Config config;

    public ControllerEssBalancingImpl() {
        super(OpenemsComponent.ChannelId.values(),
              Controller.ChannelId.values(),
              ControllerEssBalancing.ChannelId.values());
    }

    @Activate
    private void activate(ComponentContext context, Config config) {
        super.activate(context, config.id(), config.alias(), config.enabled());
        this.config = config;
    }

    @Override
    @Deactivate
    protected void deactivate() {
        super.deactivate();
    }

    @Override
    public void run() throws OpenemsNamedException {
        if (!this.ess.isOnGridOrUndefined(m -> this.logWarn(this.log, m))) {
            return;
        }
        int target = this.getSetGridActivePowerNextWriteValue()
                .orElse(this.config.targetGridSetpoint());
        var power = this.meter.getActivePower().getOrError()
                + this.ess.getActivePower().getOrError() - target;
        this.ess.setActivePowerEqualsWithFilter(power);
        this.ess.setReactivePowerEqualsWithoutFilter(0);
    }
}
----

(gekürzt; im Original steht die Rechnung in einer statischen Methode `+calculateRequiredPower+`, die sich einzeln testen lässt)

[#sec-was-die-teile-bewirken]
=== Was die Teile bewirken

* **`+configurationPolicy = REQUIRE+`**: Die Komponente entsteht nur, wenn eine Konfiguration existiert.
* **Konstruktor**: Alle `+ChannelId+`-Enums der implementierten Natures übergeben. Fehlt eines, existieren dessen Channels nicht und der Zugriff scheitert zur Laufzeit.
* **`+implements+`**: alle Natures aufzählen, auch Eltern-Interfaces (siehe xref:development/de/fundamentals/components-and-channels.adoc[Architektur]).
* **`+getOrError()+`**: wirft eine Ausnahme, wenn der Wert fehlt (z. B. Zähler nicht erreichbar). Der Scheduler fängt sie ab und setzt `+RunFailed+`. Wer mit fehlenden Werten anders umgehen will, nutzt `+get()+` (kann `+null+` sein) oder `+orElse(…)+`.
* **Sollwerte** an Speicher gehen über die Leistungsverteilung; Einzelheiten unter xref:development/de/fundamentals/cycle-and-ess-power.adoc[Zyklus].

[#sec-referenzen-auf-andere-komponenten]
== Referenzen auf andere Komponenten

Ein Controller bekommt Zähler und Speicher über OSGi-`+@Reference+`. Welche Instanz gemeint ist, steht in der Konfiguration (`+ess_id+`). Damit OSGi die richtige Instanz injiziert, braucht die Referenz einen **Target-Filter** mit dieser ID.

**Neuer Weg (139 Klassen):** `+@GenerateTargetsFromReferences+` aus `+io.openems.core.referencetarget+`. In `+target+` steht ein Platzhalter `+${config.ess_id}+`; ein Configuration-Plugin ersetzt ihn beim Laden der Konfiguration durch den Wert der Property. In der Annotation stehen die Namen der Referenzen (Feldname oder, bei Setter-Methoden wie `+setModbus+`, der Referenzname).

**Alter Weg (noch in wenigen Klassen):** eine zusätzliche Property `+ess_target+` in der Config und im `+activate()+` der Aufruf `+OpenemsComponent.updateReferenceFilter(cm, servicePid(), "ess", config.ess_id())+`. Das schreibt den Filter in die Konfiguration und löst eine Neuaktivierung aus.

Optionen der Referenz:

[cols="2*",options="header"]
|===
| Option
| Wirkung

| `+cardinality = MANDATORY+`
| Ohne passende Komponente wird der Controller nicht aktiviert.
| `+cardinality = OPTIONAL+` / `+MULTIPLE+`
| keine oder eine / beliebig viele Komponenten; bei `+policy = DYNAMIC+` muss das Feld `+volatile+` bzw. eine thread-sichere Liste sein.
| `+policy = STATIC+`
| Ändert sich die Referenz, wird die Komponente neu aktiviert. Einfach und sicher.
| `+policy = DYNAMIC+`
| Referenz wird zur Laufzeit ausgetauscht, ohne Neuaktivierung.
| `+policyOption = GREEDY+`
| bindet sofort eine besser passende Komponente, sobald sie erscheint.
|===

Der Filter `+(enabled=true)+` sorgt dafür, dass deaktivierte Komponenten nicht gebunden werden.

[#sec-weitere-uebliche-bausteine]
== Weitere übliche Bausteine

* **`+debugLog()+`**: liefert eine kurze Zeichenkette, die „Controller Debug Log“ jede Sekunde ausgibt (z. B. `pass:c["L:" + getActivePower().asString()]`).
* **`+ModbusSlave+`**: macht Channels über die Modbus/TCP-API lesbar oder schreibbar (`+getModbusSlaveTable()+`).
* **`+EventHandler+`**: für Arbeit außerhalb von `+run()+` in einem Zyklus-Ereignis; die Topics stehen in der `+@Component+`-Property `+EventConstants.EVENT_TOPIC+`.
* **Uhr**: `+componentManager.getClock()+` statt `+Instant.now()+`; in Tests lässt sich die Uhr dann steuern.
* **Logging**: `+this.logInfo(log, …)+`, `+logWarn+`, `+logError+` aus `+AbstractOpenemsComponent+` stellen die Komponenten-ID voran.
* **`+readme.adoc+`**: wird in die offizielle Dokumentation übernommen.

[#sec-checkliste-neues-bundle]
== Checkliste neues Bundle

. Verzeichnis `+io.openems.edge.<bereich>.<name>+` mit `+bnd.bnd+`, `+src+`, `+test+`, `+readme.adoc+` anlegen (am einfachsten ein ähnliches Bundle kopieren).
. Factory-PID in `+@Component(name = …)+` eindeutig wählen; Schema z. B. `+Controller.Ess.Xyz+`, `+Meter.Hersteller.Typ+`.
. Test mit `+ComponentTest+`/`+ControllerTest+` schreiben (xref:development/de/testing/component-tests.adoc[Tests]).
. `+./gradlew :<bundle>:test+` und `+:<bundle>:checkstyleMain+` ausführen.
. Bundle in `+io.openems.edge.application/EdgeApp.bndrun+` unter `+-runrequires+` eintragen, damit es in der Edge-JAR enthalten ist.
. xref:development/coding-guidelines.adoc[Coding Guidelines] beachten und `+./tools/prepare-commit.sh+` ausführen.
