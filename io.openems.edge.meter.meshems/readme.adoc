= MeshEMS OpenAMI Meters

Discrete device driver for the MeshEMS OpenAMI metering board, which publishes its SunSpec meter data as JSON over MQTT.

== Overview

This bundle integrates the https://github.com/energy-iot/meshems-openami-metering[MeshEMS OpenAMI metering icon:github[]] application running on MeshEMS (NESL 865B / ESP32-S3) hardware. The board reads one or more physical meters, maps them onto SunSpec models and publishes each reading as a flat JSON object over MQTT through the OpenEMS MQTT bridge.

Unlike the generic `io.openems.edge.meter.mqtt` bundle, the SunSpec-field-to-Channel mapping here is *baked into code and unit-tested* rather than operator-configured. Two components are provided: a single-phase tenant meter (SunSpec model 11) and a three-phase subpanel meter (SunSpec model 213).

The inverter side of a MeshEMS site is handled separately by the sibling https://github.com/energy-iot/meshems-sunspec-gateway[meshems-sunspec-gateway icon:github[]] firmware, which exposes a Modbus SunSpec interface consumed through OpenEMS's built-in Modbus SunSpec support.

== Protocol

The board publishes under a per-device topic root:

----
openami/StreetPoleEMS_<device-id>/meter_N        <- model 11, single-phase tenant meter (one per tenant, N = 0, 1, 2, ...)
openami/StreetPoleEMS_<device-id>/subpanel_3Ph   <- model 213, three-phase subpanel meter
----

Each message is a flat JSON object whose `model_id` field identifies the SunSpec model. Every field is in SunSpec engineering units: voltage in Volt, current in Ampere, active power in Watt, reactive power in var, frequency in Hertz and energy in Watt-hours.

=== SunSpec Model 11 (single-phase) field mapping

.Example payload
----
{"model_id":11,"Phase":0,"Hz":50.02,"PhA":2.834,"PhV":228.5,"PhW":616.7,
 "VA":647.7,"Var":198.2,"PF":0.952,"TotWhImport":100286.4,"TotWhExport":0}
----

[cols="1,2,1", options="header"]
|===
| JSON field | Channel | Scale
| `PhV` | VOLTAGE (and VOLTAGE_Lx for the configured phase) | x1000 (V -> mV)
| `PhA` | CURRENT (and CURRENT_Lx) | x1000 (A -> mA)
| `PhW` | ACTIVE_POWER (and ACTIVE_POWER_Lx) | x1 (W); negated if `invert`
| `Var` | REACTIVE_POWER (and REACTIVE_POWER_Lx) | x1 (var); negated if `invert`
| `Hz` | FREQUENCY | x1000 (Hz -> mHz)
| `TotWhImport` | ACTIVE_CONSUMPTION_ENERGY | x1 (Wh); swapped with export if `invert`
| `TotWhExport` | ACTIVE_PRODUCTION_ENERGY | x1 (Wh); swapped with import if `invert`
|===

The per-phase L1/L2/L3 channels are derived from the aggregate values onto the phase selected by the `phase` configuration.

=== SunSpec Model 213 (three-phase) field mapping

.Example payload (relevant keys)
----
{"model_id":213,"Hz":50.01,
 "AphA":2.5,"AphB":3.0,"AphC":1.5,
 "PhVphA":230.0,"PhVphB":231.0,"PhVphC":229.0,
 "VarphA":100.0,"VarphB":120.0,"VarphC":80.0,
 "WphA":575.0,"WphB":672.0,"WphC":345.0,
 "TotWhImport":123456.0,"TotWhExport":654.0}
----

[cols="1,2,1", options="header"]
|===
| JSON field | Channel | Scale
| `PhVphA` / `PhVphB` / `PhVphC` | VOLTAGE_L1 / _L2 / _L3 | x1000 (V -> mV)
| `AphA` / `AphB` / `AphC` | CURRENT_L1 / _L2 / _L3 | x1000 (A -> mA)
| `WphA` / `WphB` / `WphC` | ACTIVE_POWER_L1 / _L2 / _L3 | x1 (W); negated if `invert`
| `VarphA` / `VarphB` / `VarphC` | REACTIVE_POWER_L1 / _L2 / _L3 | x1 (var); negated if `invert`
| `Hz` | FREQUENCY | x1000 (Hz -> mHz)
| `TotWhImport` | ACTIVE_CONSUMPTION_ENERGY | x1 (Wh); swapped with export if `invert`
| `TotWhExport` | ACTIVE_PRODUCTION_ENERGY | x1 (Wh); swapped with import if `invert`
|===

The aggregate VOLTAGE (average), CURRENT, ACTIVE_POWER and REACTIVE_POWER (sums) are derived automatically from the per-phase channels. The model-213 payload also carries per-phase power-factor, apparent-power, THD, harmonics and granular energy totalizers; these are not mapped.

== Components

This bundle implements the following OpenEMS Components:

=== <<_meter_meshems_single_phase,Meter MeshEMS Single-Phase>>

*Name*: Meter MeshEMS Single-Phase

*Factory-PID*: `Meter.Meshems.SinglePhase`

.Implemented Natures/Interfaces
* MeterMeshemsSinglePhase
* ElectricityMeter
* SinglePhaseMeter
* OpenemsComponent
* MqttComponent

*Description*: Subscribes to a single-phase tenant meter topic (`openami/<device-id>/meter_N`) and applies the baked-in SunSpec model-11 mapping. The measured value is placed on the configured phase.

.*Configuration*:
* `id` (String): Component ID for unique identification (default: "meter0")
* `alias` (String): Human-readable alias for the component
* `enabled` (Boolean): Enable/disable this component (default: true)
* `type` (Enum): Meter type - GRID, PRODUCTION, or CONSUMPTION_METERED (default: CONSUMPTION_METERED)
* `phase` (Enum): Which phase this meter is connected to - L1, L2 or L3 (default: L1)
* `invert` (Boolean): Inverts all power values and swaps production/consumption energy (default: false)
* `mqttBridgeId` (String): ID of the MQTT bridge component (default: "mqtt0")
* `topic` (String): The MQTT topic filter to subscribe to

=== <<_meter_meshems_three_phase,Meter MeshEMS Three-Phase>>

*Name*: Meter MeshEMS Three-Phase

*Factory-PID*: `Meter.Meshems.ThreePhase`

.Implemented Natures/Interfaces
* MeterMeshemsThreePhase
* ElectricityMeter
* OpenemsComponent
* MqttComponent

*Description*: Subscribes to a three-phase subpanel meter topic (`openami/<device-id>/subpanel_3Ph`) and applies the baked-in SunSpec model-213 mapping. Per-phase channels are set directly; aggregate values are derived from them.

.*Configuration*:
* `id` (String): Component ID for unique identification (default: "meter0")
* `alias` (String): Human-readable alias for the component
* `enabled` (Boolean): Enable/disable this component (default: true)
* `type` (Enum): Meter type - GRID, PRODUCTION, or CONSUMPTION_METERED (default: CONSUMPTION_METERED)
* `invert` (Boolean): Inverts all power values and swaps production/consumption energy (default: false)
* `mqttBridgeId` (String): ID of the MQTT bridge component (default: "mqtt0")
* `topic` (String): The MQTT topic filter to subscribe to
